# PDF Editor 真实业务文档验收规范

## 1. 目的与边界

本规范用于 PDF Editor V1.2 上线前的真实业务文档验收。自动生成 fixture、单元测试和视觉回归通过，不能替代真实业务文档验收。

真实业务文件只允许在获得授权的隔离环境中使用。进入仓库前必须完成脱敏；包含客户名称、人员信息、联系方式、账号、合同金额、签章证书、内部编号或其他敏感信息的原件不得提交 Git。

## 2. 最低样本覆盖

每次 Production Release 至少覆盖以下六类样本，每类至少一份：

| 类别 | 目录 | 最低验收重点 |
| --- | --- | --- |
| 普通文本 PDF | `tests/fixtures/pdf-editor/simple/` | 文本查找、替换、删除、加字、分页操作及可复制性 |
| 复杂字体 PDF | `tests/fixtures/pdf-editor/font/` | 中文、嵌入字体、子集字体、缺字处理及版式保持 |
| 图片 PDF | `tests/fixtures/pdf-editor/image/` | 图片新增/替换、bbox、transform、非目标区域及无叠图 |
| 扫描 PDF | `tests/fixtures/pdf-editor/scanned/` | 正确识别为扫描型；不得把无 OCR 能力误报为可编辑文本 |
| 企业盖章文件 | `tests/fixtures/pdf-editor/complex/` | 印章和签名区域不得被非目标操作破坏；只使用脱敏或合成印章 |
| 多页表格文件 | `tests/fixtures/pdf-editor/complex/` | 跨页表格、页序、分页、行列边框、页眉页脚及非目标页一致性 |

扫描件的 OCR 重绘不属于 V1.2 范围。该类样本用于验证分类、拒绝行为、页面级操作和输出完整性，不用于声明 OCR 编辑通过。

## 3. 样本准入

1. 确认文件所有者已授权用于测试。
2. 使用不可逆方式移除或替换个人信息、客户信息、业务编号、金额、签章证书等敏感内容。
3. 企业盖章样本只能使用合成章、测试章或完全脱敏且无法律效力的图像。
4. 计算输入文件 SHA-256；验收记录只使用测试编号和哈希，不记录真实客户名称。
5. 将样本置于对应的本地 fixture 子目录；除目录规范文件外，不得提交 Git。
6. 在隔离输出目录运行，禁止覆盖输入原件。

PowerShell 计算哈希示例：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '<sanitized-input.pdf>'
```

## 4. 执行流程

对每个样本执行以下流程：

1. 记录测试编号、样本类别、输入文件 SHA-256、页数和 PDF 类型。
2. 为样本选择至少一个有代表性的 V1.2 操作；高风险操作需单独输出，不得串联掩盖结果。
3. 保存操作参数、输出文件名、输出 SHA-256 和执行日志。
4. 确认执行、保存后重开、语义、视觉、几何/布局五层验证结果。
5. 将输入与输出逐页渲染为图片，按 100% 比例人工检查目标区域和非目标区域。
6. 记录发现的问题、严重级别、复现步骤和处置结论。
7. 只有必测样本全部完成且不存在未关闭的 P0/P1 问题时，真实业务验收才可标记为 PASS。

## 6. 视觉验收要求

- 逐页比较输入与输出，不只检查被编辑页面。
- 文本操作检查字体、字号、颜色、基线、换行、遮挡和不可见残留。
- 图片操作检查位置、尺寸、旋转、裁剪、清晰度、旧图残留和叠图。
- 页面操作检查页数、页序、旋转、空白页、页眉页脚和书签影响。
- 中文页码检查 `第`、`页`、`共` 等字形真实可见，不以文本提取成功代替视觉通过。
- 企业盖章与表格文件重点检查非目标区域像素、印章完整性、边框和跨页对齐。

## 7. 问题分级与发布门禁

| 等级 | 定义 | 发布处理 |
| --- | --- | --- |
| P0 | 文件损坏、数据丢失、错误覆盖原件或安全问题 | 阻断发布 |
| P1 | 主要内容错误、明显版式破坏、印章或表格被破坏 | 阻断发布 |
| P2 | 局部视觉偏差但不影响内容正确性 | 评估后决定并记录风险 |
| P3 | 文档、提示或易用性问题 | 可进入后续修复计划 |

验收完成后，只提交脱敏的测试记录、哈希和问题摘要。真实文件、原始渲染图和可能还原业务信息的日志不得进入仓库。
