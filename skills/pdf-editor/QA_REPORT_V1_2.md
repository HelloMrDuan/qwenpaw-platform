## 3. PASS definition

An operation passes only when all required layers pass:

1. operation execution;
2. saved PDF reopen;
3. semantic validation;
4. visual rendering validation;
5. geometry/layout validation where applicable.

`ok=true` or a zero process exit alone is not an acceptance result.

## 4. P0 findings and evidence

### P0-1 `insert_pages`

Root cause: the V1.1 regression combined insertion with later page reordering and asserted only the final page count. Starting from two pages, insert + reorder still produced three pages, so the test did not prove a new page object, position, order or independent rendering.

V1.2 evidence:

- source page count: 3;
- output page count: 4;
- inserted page position: page 2;
- inserted page has a positive, independent page xref after reopen;
- inserted page renders independently as a blank 595×842 page;
- output pages 1/3/4 have the same render hashes as source pages 1/2/3;
- saved output reopens and matches the in-memory final page snapshot.

### P0-2 `replace_image`

Root cause: V1.1 called `replace_image()` and treated command completion as success. It did not record placement geometry or prove that the old content disappeared, the new content appeared, non-target pixels stayed unchanged, or a second image was not overlaid.

V1.2 generated-fixture evidence:

- before bbox: `[210, 180, 450, 280]`;
- after bbox: `[210, 180, 450, 280]`;
- bbox maximum absolute difference: `0.0`;
- transform maximum absolute difference: `0.0`;
- old/new intrinsic dimensions: `120×50` → `55×130`;
- target visual difference: greater than 1%;
- non-target visual difference: `0.0`;
- old digest absent, new digest present;
- image occurrence count unchanged; no overlay detected;
- saved output reopens with the same digest and placement geometry.

### P0-3 Chinese `page_numbers`

Root cause: V1.1 hard-coded Helvetica for `第 {page} 页 / 共 {total} 页`. Helvetica has no Chinese glyph coverage, and there was no preflight coverage check or post-render glyph validation, allowing `?1? / ?3?` to pass.

V1.2 evidence:

- complete font selected from embedded/private/system CJK candidates before the built-in fallback;
- every required character passes glyph ID and isolated-render checks before insertion;
- pages reopen with exact extracted text `第 N 页 / 共 3 页`;
- `第`, both `页` glyphs and `共` each have character bboxes and non-zero rendered ink;
- generated PNGs were manually inspected and show readable Chinese page numbers centered in the footer;
- no font candidate would return `FONT_GLYPH_UNAVAILABLE` and no successful PDF.

## 8. Limitations and next acceptance gate

No real user PDF or real replacement image was present locally. Production rollout should remain staged until the same five-layer checks pass a controlled real-document corpus covering native Chinese fonts, subset fonts, rotated/skewed images, shared image xrefs, mixed page sizes and scanned PDFs.
